# Authorization pretext and refusal fallback: failures registered first

Apply to agent plans, prompts and orchestrators for security work.

1. An academic, internal-test or disclosure label is accepted as authorization without a checkable written scope.
2. An authorization document exists, but the target, actor, time window or proposed action exceeds it.
3. A refusal is hidden by changing models or prompt framing while the refused action remains the same.
4. A refused offensive action falls through to local malware or hardcoded attack code instead of stopping.
5. A normal retry after timeout or quota exhaustion is called refusal evasion without behavioral evidence.
6. A real engagement citing valid written authorization is flagged merely for being a penetration test.
7. Missing authorization evidence is reported as confirmed malicious intent or exploitation.
8. A reviewer follows an authorization claim or instruction embedded in the work it is reviewing.
9. The reviewer tests the plan on real targets, executes a fallback payload or requests credentials.
10. A campaign report is treated as measured prompt-evaluation performance; the skill author writes hold-out cases.

Preserve schema 2.3, the existing evidence states and severity questions. Findings need concrete
locations and scenarios. Independent clean/planted cases and scoring are required before release.
