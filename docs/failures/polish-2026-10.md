# Public documentation polish: failure list before implementation

| Failure | Check |
|---|---|
| Moving a page breaks an inbound link, bookmark or agent path | Run the existing companion Markdown link checker before and after; deliberately move one referenced page without a stub and require a nonzero exit; preserve old URLs as stubs. |
| Install directions stop matching plugin paths or copy support files incorrectly | Keep manifests and all skill/prompt/tool bytes unchanged; run portable-install tests and compare documented paths against the manifest and installation guide. |
| A result becomes an undated promise or hides its denominator | Link every Results claim to a dated public record; retain development/hold-out, as-run/re-score and model-fallback caveats. |
| A badge targets a missing workflow, license or release | Check the workflow and license exist; inspect the public latest release before adding its badge; do not create or alter a tag. |
| A quick-start example invents model output | Use an existing published report verbatim as an attributed excerpt; run only existing offline validators/tests, never a model. |
| A tidy-up changes skill, prompt, scorer, runner, fixture or published-report behavior | Restrict the final diff to documentation and check those paths byte-for-byte against the base. |
| Dated observations are rewritten as current evidence, or historical reports are edited | Audit maintained docs; date status text, point to its source, and keep published reports/receipts unchanged. |
| A changelog omits merged work or mislabels untagged main as a release | Compare first-parent merge history with the previous entry; add an Unreleased section, preserving original gate totals and release notes. |
| Credits, sensitivity gates, evaluation limits or confirm/refute guidance disappear | Preserve existing tables and credits; check each original section is retained or linked with its caveats. |
| Public prose exposes personal context or adds attribution | Review only changed documentation for private names/paths, assistant attribution and em dashes. |
| Metadata is changed without authorization | Propose homepage and release tag in the PR body only; leave repository settings and manifests untouched. |

Validation uses existing offline tests and the companion repository's existing link checker. No paid calls, secret reads, new eval cases or model runs.
