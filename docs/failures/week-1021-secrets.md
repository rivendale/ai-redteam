# Secrets-placement lens: failures registered first

Apply to plans and architectures that introduce, move or rely on a secret.

1. A secret is named without its storage location or the principal that can read it.
2. Hosted environment variables, consoles, CI, backups or other third-party copies are omitted.
3. Encryption at rest is treated as proof that the service operator cannot obtain plaintext.
4. The plan omits the permissions, data access and spending power exposed by that secret.
5. Spend/scope limits are absent or a usage alert is represented as an enforced cap.
6. A written rotation path omits revocation, dependent updates or verification that the old key fails.
7. The plan cannot explain rotation within one hour, but the required High is missed.
8. An input gap is called a confirmed deployed breach; a complete bounded plan receives invented findings.
9. The review requests, prints or copies key values to make its inventory.
10. The new lens changes the finding schema or makes unscored performance claims.

Preserve schema 2.3, evidence states and the existing confirm-or-refute process. The inability to
rotate within one hour is a plan deficiency, not evidence that a compromise occurred.
Independent cases and scoring are required before shipping the candidate.
